## 创新性：25%

作品主线：老人本人收到材料后独立核实；把“材料是否有合成线索”和“内容是否提出高风险要求”分开，避免真假声音代替身份核实；Agent按实际报告检索官方依据并留下可审查工具记录。

模式创新材料：个人端免费核实＋社区/养老机构本地部署与维护服务的可行性假设；误报/漏报反馈进入人工复核，不自动污染模型。见商业与社会价值说明。

交互创新仍需前端展示三项证据、来源及工作流进度。当前不改前端，不能说交互创新已全面展示，更不能保证创新性得满分。

- 解决方案有效性5%：有实测报告、正反对照、分支故障处理及新增人工反馈接口；尚缺老人真实可用性试用、跨平台与新生成器独立测试。因此只能说已有验证，不能说现实防骗效果全部达标。

## 新接口与文件

- POST /api/cases/{id}/advice：原接口保留，内部升级为LangChain Agent；返回旧字段并增加mode、run_id、selection、corpus、duration_seconds、safety。
- POST /api/cases/{id}/agent-review：相同后端核实流程，单并发保护。
- POST /api/cases/{id}/agent-events：SSE进度与最终结果，给未来前端使用。
- GET /api/agent/capabilities：工具列表、实际框架版本和知识库版本。
- POST /api/cases/{id}/feedback：有用/无用/疑似误报/疑似漏报；只进入复核，不自动训练。
- GET /api/agent/metrics：匿名计数，不是准确率或防骗人数。
- backend/agent_model.py：本地模型LangChain适配器。
- backend/agent_review.py：Agent工具、执行边界、证据校验、兜底。
- backend/rag.py：混合检索和审核资料。
- backend/agent_store.py：本地步骤审计与反馈；删除报告联动删除。
- verify_agent_upgrade.py：检索对照；加--live运行真实本地Agent测试。
- test_agent_upgrade.py：工具、注入、反馈、删除和API回归。
