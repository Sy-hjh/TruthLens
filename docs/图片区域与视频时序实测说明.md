# 图片区域与视频时序：实际做了什么

2026-11-11。回应用户对三图块、整图AI生成、多区域和连续视频的质疑。本轮未把弱模型强行上线。

## 图片是完整图块，不是随机挑像素

视觉模型接收RGB图块，把像素组织成学习到的特征，再输出分类信号。它没有一条能直接读取的“AI像素标记”，代码也不能可靠指出具体哪种纹理导致判断。整张图都由AI生成，不代表每个区域有相同强度的可检测信号：天空、皮肤、衣服、文字的内容不同，模型特征不同，裁剪还会丢掉整体关系。真人图的局部也可能误报。

现用作者方案：短边超过576像素就等比例缩小，低于528就等比例放大，再沿长边取起始、中央、末端三个528×528图块。三个图块可能高度重叠，小方图甚至可能完全重复。平均的是原始logit，再转成分数；不是简单平均网页三个分数。新报告保存实际坐标并展示可展开区域示意，框不是异常位置。

## 为什么没有直接增加到九宫格

已经实际比较：按路径SHA固定取已观察过的balanced-v1验证80张、测试80张，每组40真人、40生成，同一张图测试四种方案。九宫格窗口边长为原图短边60%，取3×3位置再缩放到528像素。它只是一个候选，不代表所有多区域方法。

固定强提醒阈值0.5，不按测试调参：

| 方案 | 验证80张：真人误报 / AI漏检 | 测试80张：真人误报 / AI漏检 |
|---|---|---|
| 现用3图块 | 0 / 9 | 0 / 2 |
| 整图 | 0 / 9 | 0 / 2 |
| 九宫格 | 3 / 15 | 0 / 4 |
| 整图+九宫格 | 3 / 15 | 0 / 4 |

所以这套九宫格没有替换现用方案。它可能因局部上下文损失、放大和尺度变化而变差，但具体原因还需进一步消融，不能仅凭这些数值断定。该子集曾参与旧评测，属于后续对比，不是新的独立准确率，更不能把小子集的97.5%当通用成绩。完整输出：`reports/image-regions-comparison.json`。

## 视频之前说得过宽

现用GenD在8个均匀时间点检查画面，再平均；不是连续时序，也不检查口型同步。界面名称已明确为“视频抽帧换脸检查”。旧时序方案曾测试但表现较差：SIFTA诊断平衡准确率65.5%，X-CLIP+VideoMAE融合300条最终组为83.75%，现用GenD另一179条组为92.89%。这些组不同，不构成严格同组比较，且任务主要是换脸，不能泛化为所有AI视频。

## 本轮真正跑了32个连续帧的网络

官方FTCN+TT，固定commit `853256a888bd5c4879955c06a4c5a666740f91a4`；权重SHA256 `3d08fc78174bbfdb3fbede317b95dcac9095202ed7113649eecf6e2ef5ee77d8`。只使用安全weights_only张量加载，权重严格匹配，没有随机层。它是2021年历史基线，不能冒称最新模型。

从已观察过的179条视频按源ID的SHA固定取12组36条。每视频最多4个分布在全片的片段，每片段32个原生帧率连续帧；每段共同裁剪框，逐帧检查附近人脸，避免检测框抖动制造闪烁。该裁剪不同于作者原始关键点对齐，所以结果仅代表本机适配管线。

| 同组36条，阈值0.5 | 真人12条误报 | 换脸24条漏检 | 平衡准确率 |
|---|---:|---:|---:|
| FTCN连续时序 | 0 | 15 | 68.75% |
| 现用GenD抽帧 | 2 | 0 | 91.67% |

顺序对照也实际运行：其中一个真人片段原始分数0.000312，打乱帧后0.995535。这说明网络确实对前后变化敏感，不代表高分就一定AI；人为打乱也会制造不自然运动。真实顺序的换脸视频仍可能连贯，旧模型继续漏检。没有据此上线旧网络或平均两个分数伪装诈骗概率。完整结果：`reports/ftcn-contiguous-comparison.json`。这是后续小规模诊断，不是全新独立测试。

## 新模型的状态不能混淆

查阅了2025年[FakeSTormer官方源码](https://github.com/10Ring/FakeSTormer)，固定commit `c5b5f75100b878212a192c00013275f275f86182`。官方Dropbox页面访问超时，公开ZIP约1,978,415,158字节，本轮仅取得部分字节，没有完整权重，没有完成推理。不是电脑权限不足，不把代码下载说成模型跑通，也不把论文AUC贴为项目成绩。

也查阅了2026年[STALL官方实现](https://github.com/OmerBenHayun/STALL)：采用DINOv3特征和真实视频参考分布的空间/时间统计。它与当前CLIP分数曲线不同，尚未实现，网页没有冒称支持。

真实的后续升级需要：近期模型完整权重、连续片段输入、独立声音检查；口型同步若做要另外验证；再按源视频分组检查新生成器、转发压缩、短时替换、正常剪辑反例。当前时序上线缺口仍然存在，不能用“增加区域”或“时序”几个字掩盖。

## 代码入口

- `compare_image_regions.py`：四种图片采样对照，按图保存进度，不自动替换。
- `backend/image_regions.py`：候选九宫格与现用实际坐标；区域不是异常证据。
- `ftcn_candidate.py`：隔离的FTCN网络与32连续帧采样，只供独立研究进程，不能导入网站进程。
- `evaluate_ftcn_candidate.py`：固定36条同组比较和顺序对照，不自动上线。
- 原作者源码和隔离实验依赖保留在runtime，不冒称团队原创，不打包分发未经明确许可的源码。

另查阅了ICCV2025 [D3官方实现](https://github.com/Zig-HS/D3)，用二阶时间特征分析整段生成视频，尚未在亲安实现或实测；不能把研究过的方法算成已完成的功能。
