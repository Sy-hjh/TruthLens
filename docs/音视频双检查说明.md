# 音视频双检查（2026-11-13）

用户新要求取代此前“音视频不转文字”的产品约束。不是替换已有合成检测，而是并行含义、顺序执行的两条独立证据链。

## 实际流程

音频：提取16kHz波形→原VeriSpoof/XLS-R声学检查→本地ASR转写→本地Qwen提取要求与证据组合提醒。视频：保留有序GRU画面检查，并对音轨执行上述两条检查。原阈值、编码器、声学模型不因文字结果改变，也不把各分数相加成诈骗概率。

转写优先使用已安装的Paraformer，失败时沿用已有Whisper回退；按30秒分段最多前3分钟。内容分析复用已存在的本地文字能力，不声称新增训练或准确率提高。文字仅来源于实际转写/用户明确校正，不使用文件名、背景描述编造说话内容。真人也可能有可疑要求，AI声也可以是普通内容；任何阴性都不证明安全。

backend/speech_content.py分别捕获转写与语义分析失败。无音轨/静音明确不可用；声学出错但仍取得波形时也可继续做转写。文字失败保留已有合成分数。原始上传媒体仍处理后删除，转写文字随报告保留，可由历史删除。

## 接口与界面

/api/analyze不加新必填字段。报告新增speech_analysis，独立于modules；transcript不再固定disabled。语义内容卡显示疑似套路、逐字原话、公开案例、转写核对及校正标记。原视频/音频卡保持自己的方法和分数，不把文字警报标成AI声音警报。

新增POST /api/cases/{id}/speech-text，multipart text，1–4000字。只允许音视频报告，保留原转写original_text、corrected标记，内容input_basis=user_corrected_transcript；原modules保持不变。原来的/transcript退休接口仍返回410，截图仍用/chat-text。新校正并不重新分析声音，也不能改变音视频模型分数。

SpeechContent.tsx负责内容卡，Report.tsx接入，api.ts增加字段，首页说明同步更改。旧报告缺speech_analysis提示重传，不给历史补造内容。打印、JSON导出与历史兼容。

## 工程验证与失败记录

测试包括虚构中文借款TTS、普通内容TTS、作者真实带声视频，以及转写校正前后modules完全相同。虚构TTS仅作工程控制，绝非真人克隆或真实诈骗录音。公开材料结果不冒充通用准确率。

初次实测发现普通对照中的“不涉及转账和验证码”被语言模型误标为索取验证码，保留runtime/speech-dual-before-credential-guard.log。修正证据校验，要求实际索要/提供/发送等操作依据，不能仅因出现验证码名词就报警；补充六位数字与普通提及对照。仍可能有误识别和新套路漏检，不能宣称完美。

新增test_speech_content.py覆盖ASR/语义失败隔离、空转写、实际转写入参、文字校正保持模型输出及验证码边界；旧test_audio_isolation.py更新为新需求下的分数隔离。verify_speech_dual.py是真实HTTP对照，reports/speech-dual-check.json保存实际输出。运行现有测试无需重新训练。
